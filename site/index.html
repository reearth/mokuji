Search,
without a server. サーバーなしで、検索。

Mokuji is a file format for search indexes, with libraries and a command line tool to build and read it. The file is uploaded once; each query reads only the few pieces it needs, by HTTP range requests. Mokuji は、検索インデックスのファイル形式と、それを作って読むライブラリとCLIです。ファイルは置くだけ。検索のたびに読むのは、そのうち必要な数か所だけです。

      01

      The index is a file.
      Put it where your files go.       インデックスは、ファイル。
      ファイルを置ける場所に置く。

      Search usually means a service: a cluster to run, scale and patch, or an API that bills by the request. Mokuji publishes the index instead, as one file that never changes once written, on any storage that honours Range — S3, R2, a CDN. A browser, a Worker or Node opens it with a reader of 13 KB and fetches only the parts a query touches. 検索といえば、ふつうはサービスです。動かし、増やし、更新し続けるクラスタか、リクエストごとに課金される API。Mokuji はかわりにインデックスを公開します。書いたら変わらないファイル1つを、Range に応えるストレージ（S3、R2、CDN）に置くだけ。ブラウザ、Worker、Node が 13 KB の reader で開き、検索が触れる部分だけを取りに行きます。

      02

      One layout,
      many kinds of search.       1つの形式で、
      いろいろな検索。

      The format does not decide what a term is or what a result carries. A geohash cell can be a term, and the polygon it falls in the result — which is reverse geocoding, with no spatial index.       03

      What a query costs
      is written down.       1回の検索のコストは、
      仕様に書いてある。

      2k + m

      For a query of k terms returning m documents, a reader makes at most 2k + m range reads, plus one when it opens the file. The bound is in the specification, and the conformance suite checks the count as well as the answers, for every implementation: the Rust crates, the TypeScript, Python and Go readers, and a Python builder written from the specification alone. k 語で m 件を返す検索の読み出しは、多くて 2k + m 回。ファイルを開くときにもう1回。この上限は仕様に書いてあり、conformance スイートは答えだけでなく読み出しの回数も確かめます。Rust の実装、TypeScript・Python・Go の reader、仕様だけから書いた Python のビルダー、どれも同じケースに答えます。

      1. 1

        Get a fileファイルを用意する

        Download one, such as the files this page searches (listed here, each with its licence), or build your own: one document per line, its text and its payload. このページが検索しているファイル（一覧。ライセンスも書いてあります）のようにダウンロードするか、自分で作ります。1行に1件、テキストとペイロード。

mokuji build places.tsv places.mokuji

      2. 2

        Put it up置いて公開する

        On any storage that answers Range requests: S3, R2, a CDN. For a page on another origin, allow CORS and expose Content-Range. Range リクエストに応えるストレージならどこでも。S3、R2、CDN。別オリジンのページから読むなら、CORS を許可して Content-Range を公開します。 

        aws s3 cp postal.mokuji s3://my-bucket/

npx wrangler r2 object put my-bucket/postal.mokuji \
  --file postal.mokuji --remote

      3. 3

        Read itJS で読む

        In a browser, a Worker or Node, with a reader of 13 KB and no dependencies. ブラウザでも Worker でも Node でも。13 KB の reader で、依存はありません。

      05

      Offline,
      just keep the file.       オフラインなら、
      ファイルを置いて終わり。

      No storage and no network. Keep the file on disk, in your app or on the device, and ask it from the command line or from the library. The search makes no request, and reads only the parts it needs, not the whole file. ストレージも通信もいりません。ファイルを手元に、アプリの中や端末に置いて、コマンドラインかライブラリで引くだけ。検索は通信をせず、ファイル全体ではなく必要な部分だけを読みます。

      Held whole, it stays small. The 2,521 sections of the PLATEAU specifications, ranked and with a snippet from each result's text, take 1.49 MB; bleve takes 6.8 MB for the same, 4.1 MB gzipped. One corpus, measured by us: the conditions are in the README. まるごと持っても小さいまま。PLATEAU 仕様書の 2,521 節を、順位付きで、結果ごとに本文のスニペットも出せる形にして 1.49 MB。同じことを bleve でやると 6.8 MB、gzip しても 4.1 MB です。私たちが1つの corpus で測った数字なので、条件は README に書いてあります。
