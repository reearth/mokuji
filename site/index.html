Search,
without a server. サーバーなしで、検索。

Mokuji turns a search index into one file you upload. Each query reads only the few pieces of it that it needs, by HTTP range requests. Mokuji は、検索インデックスを置くだけのファイル1つにします。検索のたびに読むのは、そのうち必要な数か所だけ。HTTP の Range リクエストで読みます。

      01

      The index is a file.
      Put it where your files go.       インデックスは、ファイル。
      ファイルを置ける場所に置く。

      Search usually means a service: a cluster to run, scale and patch, or an API that bills by the request. Mokuji publishes the index instead, as one file that never changes once written, on any storage that honours Range — S3, R2, a CDN. A browser, a Worker or Node opens it with a reader of 13 KB and fetches only the parts a query touches. 検索といえば、ふつうはサービスです。動かし、増やし、更新し続けるクラスタか、リクエストごとに課金される API。Mokuji はかわりにインデックスを公開します。書いたら変わらないファイル1つを、Range に応えるストレージ（S3、R2、CDN）に置くだけ。ブラウザ、Worker、Node が 13 KB の reader で開き、検索が触れる部分だけを取りに行きます。

      Goes awayなくなるもの
      A search server, and keeping it up検索サーバーと、その運用
      Charges per request to a search API検索 API のリクエスト課金
      Remains残るもの
      A file, and somewhere static to put itファイルと、それを置く静的な場所
      A reader in your pageページの中の reader

      This page works that way: it is static, and the files it searches sit on object storage behind a CDN. このページもそうです。ページ自体は静的で、検索しているファイルは CDN の裏のオブジェクトストレージに置いてあります。

      02

      One layout,
      many kinds of search.       1つの形式で、
      いろいろな検索。

      The format does not decide what a term is or what a result carries. A geohash cell can be a term, and the polygon it falls in the result — which is reverse geocoding, with no spatial index. Click the map. 形式は、何を語にするか、結果に何を載せるかを決めません。ジオハッシュのセルを語に、それが落ちるポリゴンを結果にすれば、空間インデックスなしの逆ジオコーディングになります。地図をクリックしてください。

        A term is a whole address, so a prefix is one contiguous range.語は住所まるごと。前方一致は、ひと続きの範囲になる。

      03

      What a query costs
      is written down.       1回の検索のコストは、
      仕様に書いてある。

      2k + m

      For a query of k terms returning m documents, a reader makes at most 2k + m range reads, plus one when it opens the file. The bound is in the specification, and the conformance suite checks the count as well as the answers, for every implementation: the Rust crates, the TypeScript reader, and a Python builder written from the specification alone. k 語で m 件を返す検索の読み出しは、多くて 2k + m 回。ファイルを開くときにもう1回。この上限は仕様に書いてあり、conformance スイートは答えだけでなく読み出しの回数も確かめます。Rust の実装、TypeScript の reader、仕様だけから書いた Python のビルダー、どれも同じケースに答えます。

      04

      Build a file.
      Read it anywhere.       ファイルを作って、
      どこからでも読む。

      Build, with the command line tool作る（コマンドラインツール）

      cargo install --git https://github.com/reearth/mokuji mokuji-cli
mokuji build places.tsv places.mokuji
mokuji search places.mokuji tokyo chuo

      Read, in a browser, a Worker or Node読む（ブラウザ・Worker・Node）

      pnpm add "git+https://github.com/reearth/mokuji.git#<commit>&path:/js"
      import { MokujiIndex } from "@reearth/mokuji";

const index = await MokujiIndex.open("https://example.com/places.mokuji");
const { payloads } = await index.complete("東京タ", 10);
