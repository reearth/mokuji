Completing a place name, from a static file

Every place in GeoNames, 12.9 million of them, under all their names, in one .mokuji file on a plain static server. Each keystroke is answered by range requests into it: none before the payload when the prefix is one the file answered ahead of time, and never more than a few when it is not.

    Each name is one term (name-list in TOKENIZERS.md), so black se is a prefix of black sea rather than a word and part of another. Places are numbered most-named first, so the first documents a prefix matches are the ones worth showing. Each is listed under its main name, which need not be the name that matched: s finds the Atlantic Ocean because one of its names in another language begins with it.

    A short prefix matches millions of names and spans hundreds of dictionary blocks. The file carries a completions section (SPEC.md §5.3.5) with the first ten places for every such prefix, held with the rest of the opening read. Any prefix without an entry is guaranteed cheap: fewer terms than the file states, and fewer bytes of postings. Green is the section answering; otherwise the dictionary did, within that bound.
